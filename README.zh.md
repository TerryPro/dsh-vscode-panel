# DSH 工作台布局

**简体中文** | [English](README.md)

为 DeepSeek Harness Web 提供三栏工作区：左侧导航、中间文件/编辑器/Git/终端、右侧 DSH 原生对话。

![DSH 工作台布局：文件目录、编辑器与原生对话](https://raw.githubusercontent.com/TerryPro/dsh-vscode-panel/main/assets/workbench-files-and-chat.png)

![DSH 工作台布局：Git 更改视图、左右对照 Diff 与原生对话](https://raw.githubusercontent.com/TerryPro/dsh-vscode-panel/main/assets/workbench-git-diff.png)

## 项目由来

DeepSeek Harness（DSH）Web 是一个 AI 编程助手客户端，官方 AppFrame 以对话为中心。它出厂时并没有能配合对话使用的代码工作台——没有文件目录、没有编辑器、没有 Git 面板、也没有终端。

本插件的目标就是**以增量方式**补上这块能力。它不 fork、也不替换 DSH 的界面，而是注册进客户端公开的 slot（侧栏底栏、侧栏工作区区域、右侧会话列），把现有 AppFrame 重排成一套 VS Code 风格的三栏工作台。原生对话、任务状态、工具与输入框都保持 DSH 原样——这个项目最早只是给 DSH 做一个「类 VS Code 面板」，如今已从最初朴素的三栏布局成长为一个完整的编辑环境。

它是一个「双半」结构的插件：

- **宿主半（Node）**——挂载在 DSH Web 服务器上的可信 JSON 接口。它提供工作区文件操作和一个加固过的 Git 命令层，并按需托管 Mermaid 运行时包。每个请求都会校验来源，并被限定在官方工作区 id 与工作区相对路径之内。
- **客户端半（React）**——浏览器 UI。它渲染侧栏、编辑器、Git 视图、终端和各类结构化视图，且只与宿主接口通信。凡官方客户端暴露能力之处，都复用 DSH 组件与设计变量，因此工作台观感与交互都是原生的。

本版本针对 DSH Web 0.2.0-rc.2 构建并测试；peer 范围同时接受 0.1.5-rc.1，两者的侧栏、右栏与底栏 slot 契约一致。

## 概览

| 区域 | 提供的功能 |
| --- | --- |
| 左栏 | 会话、文件目录、Git 更改与提交图、终端列表 |
| 中栏 | 多标签、多窗格编辑，Markdown/Mermaid/HTML/CSV/JSON/图片查看器，单文件 Diff，交互式终端 |
| 右栏 | DSH 原生对话、任务状态、工具与输入框 |

文件、Git 状态、编辑器标签和终端跟随所选**工作区**；聊天仍由当前**会话**管理。布局、图标、颜色、菜单、弹窗、悬浮提示和响应式行为都会在官方客户端提供能力时优先复用 DSH 组件与设计变量。

## 功能

### 文件与编辑

- 按需展开目录，并支持新建、重命名和删除文件或文件夹。
- 文件目录和中栏标签使用工作区 Git 状态着色：未跟踪、删除或冲突为红色，新增为绿色，修改和重命名为警告色；未跟踪状态只装饰文件本身，目录聚合其他后代状态中优先级最高的一项。
- 在同一标签栏打开多个文件；标签溢出时可在顶栏使用滚轮横向滚动。
- 右键任意标签打开 VS Code 风格菜单：关闭、关闭其他、关闭右侧、关闭已保存、全部关闭，保存、还原文件，复制路径、复制相对路径、在文件目录中显示，以及向右/向下拆分。批量关闭会逐个保留未保存草稿的确认弹窗；鼠标中键同样关闭所在标签。
- 使用 `Ctrl/Cmd + S` 保存当前文件。写入会检查 DSH 文件版本，避免静默覆盖外部修改。
- 页面可见时约每秒批量检查已打开文件；从其他软件切回页面时立即检查。未编辑的标签会自动更新，未保存草稿遇到外部修改时会提示选择重新加载或保留当前内容。
- 编辑器按 CodeMirror 的规范化文本比较修改状态，并在保存时保持文件原有的 CRLF、LF 或 CR 换行风格，避免仅因换行格式产生黄色未保存标记。
- 在文件右键菜单复制工作区相对路径或绝对路径；将 DSH 工具产生的文件索引直接打开到中栏。
- 依据文件路径解析语言并提供 24+ 种语法高亮——C/C++/C#、CSS/SCSS/Less、Go、HTML/Vue、Java、JavaScript（含 JSX/MJS/CJS）、TypeScript（含 TSX）、JSON/JSONC/JSON5、Markdown、Mermaid、PHP、Python、Rust、SQL、Shell、Dockerfile、TOML、INI/`.env`、XML/XHTML、YAML 以及 CSV/TSV。状态栏显示解析出的语言；未知类型退回纯文本。
- 常见图片以渲染预览打开，而非原始字节；其他二进制文件显示二进制变更提示。

### 多窗格编辑

- 将中栏拆分为两个窗格，每个窗格有独立的标签条、状态栏和视图开关。
- 新文件打开到当前聚焦的窗格；可将任意标签跨窗格拖拽移动，目标窗格会显示柔和的放置区高亮浮层。
- 也可从标签右键菜单的“向右拆分/向下拆分”把该标签移入另一窗格并聚焦它；已分栏时这两项自动隐藏。
- 副窗格最后一个标签关闭后自动收栏。
- 终端同样参与分栏：可并排 `终端｜文件` 或 `终端｜终端`，运行中的终端在窗格间移动时不丢会话。

### 行内 Git 变更

- 源码编辑器将当前缓冲区与 Git `HEAD` 比较，在可点击的变更边栏中以绿色显示新增、蓝色显示修改、红色标记删除位置，不给代码内容铺设底色。
- 点击标记可打开带上下文、旧/新双行号、`-`/`+` 行及字符级变更强调的局部 Unified Diff，在变更间导航，或仅还原这一块（还原只修改当前草稿且支持撤销）。
- 拖动弹层右边缘可调整宽度，也可以聚焦边缘后用方向键微调；宽度会限制在当前视口内，并在切换变更、文件和刷新页面后保留。点击弹层之外会将其关闭。
- 已暂存、未暂存和尚未保存的编辑会合并呈现，并随输入、保存、外部修改和分支切换更新。Markdown 渲染预览保持干净，切换到源码后显示这些标记。

### Markdown

- Markdown 默认以渲染后的预览模式打开，也可切换到源码编辑；分栏视图同时展示两者并同步滚动。
- 可按文件标签切换右侧大纲（目录）面板，预览与分栏模式均支持；点击标题会将预览平滑滚动到对应位置。提取大纲时会跳过围栏代码块并剥离行内标记。

### 结构化数据：CSV/TSV 与 JSON

- **CSV/TSV 表格查看器**：带冻结行号列、顶部筛选工具栏（跨所有单元格的大小写不敏感子串匹配 + 实时匹配计数）、列排序，以及能识别数字/日期/文本列并给出求和/最小/最大/均值的汇总页脚行。
- **表格模式下的编辑**：单元格就地编辑、相对活动单元格的插入/追加/删除行列、双击表头改名、`Ctrl+V` 按当前分隔符解析的区域粘贴；并有撤销/重做（`Ctrl/Cmd + Z`、`Ctrl/Cmd + Shift + Z`）和按文件持久化的列宽。所有编辑走与文本文件相同的版本校验草稿/保存管线，保留换行风格、尾随换行与 BOM。
- **JSON 查看器**：面向 `.json`/`.jsonc`，由自研零依赖、带源码偏移的解析器驱动，容忍注释、尾随逗号与不完整输入。四种视图——可交互的节点连线**图**画布（缩放、平移、可折叠卡片、点击定位）、缩进**树**（搜索保留祖先链、大数组按每页 200 条分页、展开/折叠预设按文件持久化）、将结构化窗格与源码编辑器联动的**分栏**视图，以及原始**源码**。文档大小与深度都有上限，保证超大文件依旧流畅。
- 两个查看器都在状态栏一枚开关下提供 表格/树、分栏、源码 三态，并按视图记住分栏比例。

### 图表与文档：Mermaid 与 HTML

- **Mermaid** 文件（`.mmd`/`.mermaid`）实时渲染为 SVG，做了防抖且只保留最新一次编辑，支持放大/缩小/适应/重置缩放、跟随明暗主题，报错信息会指出出错行。运行时包由宿主托管、按需加载。
- **HTML** 文件（`.html`/`.htm`/`.xhtml`）以预览打开，有三态：**静态**（锁定的 `sandbox=""` iframe + 严格 CSP，永不执行脚本）、**交互**（可运行脚本的不透明源沙箱，运行时把相对路径的 `.js`/`.css` 依赖自动打包为 blob URL，受单文件与总量大小/数量限制）、以及**源码**。编辑草稿会实时反映到预览。

### Git 工作区

- 以列表或目录树查看已暂存和未暂存更改。
- 通过明确操作完成暂存、取消暂存、放弃更改和提交；长文件名在静止时使用整行宽度，文件行悬浮后再按一个或两个按钮的实际宽度收缩，直接悬浮按钮时显示圆形底色。
- 将工作区、暂存区、历史提交或比较结果中的每个文件作为独立 Diff 标签打开。
- 使用 CodeMirror MergeView 渲染文本 Diff，包含行号、字符级变更、未修改区域折叠、左右对照/统一/行内三种始终可选的模式和长行换行。
- 从本地与远程引用构建轨道式提交图，展示分支、合并、标签、作者、时间和文件统计；滚动时自动按每页 40 条加载更早提交。
- 在原位置展开提交，按列表或目录树排列文件，并逐个打开。
- 创建、切换、重命名和安全删除本地分支，也可从指定引用或提交创建分支。
- 管理远端，并针对上游或明确指定的远端与分支执行 Fetch、快进 Pull、Push、发布分支和同步。
- 在提交菜单中复制提交号、Cherry-pick、Revert、创建分支或与当前工作区比较。

### 终端

- 通过 DSH **官方**终端服务（`@deepseek-ai/dsh-api-terminal-controller` 与宿主的 `webTerminals`）运行交互式 xterm.js 终端，不再自带任何需要本地构建的原生模块。插件侧只是一个薄薄的模拟器，进程派生、传输和屏幕恢复都由 DSH 负责。
- 传输走 Gateway Remote 流——Web 配置下为 WebSocket 多路复用，桌面端为 IPC 桥接。
- 终端绑定工作区而非会话，可在文件和 Diff 标签旁保留多个会话，切换标签时保持屏幕内容，并在中栏宽度稳定后统一适配尺寸。
- 使用宿主机配置的 Shell：Windows 使用 `ComSpec`，类 Unix 系统使用 `SHELL`。

### 对话与布局

- 右栏继续使用 DSH 原生对话和输入流程。
- 沿用官方 AppFrame 分隔线行为调整中栏与右栏宽度；右栏默认宽度随窗口变化，大屏下可继续向宽处拖动，同时为中栏保留可用空间。
- 可从左侧活动栏收起中栏；选择文件、Diff 或终端时会自动重新展开。对话栏收起开关并列在同一条活动栏上，即使中栏关闭，两个开关也都能点到。
- 左栏底部保持 DSH 原生的上下排列：其它插件贡献的控件（例如额度读数）继续排在账户/设置行的上方，不会被挤到同一行里。
- 打开官方或第三方插件注册的**全局面板**（如「插件」页、Qoder 额度页）时，面板按 DSH 的设计显示在右栏，中栏继续显示已打开的文件，不会变空或被覆盖；关闭面板即恢复对话栏。
- 用**返回会话**控件退出任意全局面板。DSH 自己的侧栏面板行只会*选中*面板——它的处理函数是 `selectPanel(id)`，从不调用 `selectPanel(null)`——因此当工作台接管会话列表后，官方界面里没有任何能离开面板的控件。在「插件」页上，它并入该页自身的头部动作区（刷新与添加）；对其它面板、以及插件页的详情页，它出现在活动栏视图图标下方。任何时刻只会出现一个，常驻图标簇也不会位移。
- 可拖动左侧侧栏在受限范围内调整宽度；侧栏与中栏之间保留可见边界线，菜单栏下方也有分隔线。
- 即使工作区会话还没有消息，也能访问该工作区的文件与 Git。
- 对话栏变窄时会适配输入工具栏、菜单、失败信息和助手消息统计。
- 收起中栏后，对话会回到官方中间位置和原始表面颜色。

## 安装

将公开包安装到 DSH Web 配置：

```sh
dsh plugin --profile web add @lsq64737/dsh-workbench-layout
```

如果 DSH Web 正在运行，请在安装后重启。

终端复用宿主自带的终端服务，因此没有需要批准或构建的原生模块（例如 `node-pty`）——凡 DSH 内置终端可用之处，本插件终端都可用。

再次执行相同的 add 命令即可更新。卸载命令：

```sh
dsh plugin --profile web remove @lsq64737/dsh-workbench-layout
```

## 基本使用

1. 选择一个 DSH 工作区。
2. 使用左栏模式切换会话、文件、Git 和终端。
3. 选择文件、Diff、提交文件或终端，将其打开到中栏；对 Markdown/CSV/JSON/Mermaid/HTML 文件，可用状态栏开关在结构化视图、分栏和源码之间切换。
4. 拖动中栏与右栏之间的分隔线，调整编辑区和对话区宽度。
5. 使用左侧活动栏收起或恢复中栏与对话栏。

Git 功能要求所选工作区根目录本身就是 Git 仓库。远端操作使用运行 DSH 的机器上已经配置好的 Git 凭据；插件不会索取或保存远端凭据。

## 安全与隐私

- 宿主接口只解析官方工作区 id 和工作区相对路径，不接受浏览器提供的绝对路径作为文件目标。
- 拒绝访问工作区外路径和符号链接。
- 新建文件采用原子写入，保存检查版本，重命名不会主动覆盖已有项目。
- 外部文件刷新通过官方 DSH 文件系统批量比较版本；有未保存草稿时不会自动替换内容。
- 递归删除文件夹和破坏性 Git 操作需要确认。文件与文件夹删除是永久操作。
- Pull 和同步只允许快进；Cherry-pick 与 Revert 要求工作区干净，Git 报告冲突时会自动中止。
- Git 命令使用固定参数且不经过 Shell，并禁用 Git 操作中的终端凭据提示。
- HTML 预览运行在沙箱 iframe 内；交互预览运行在不透明源（opaque origin）沙箱中，不获得同源权限，且只打包受大小限额约束的相对资源。
- 日志使用工作区 id 和相对路径，不记录宿主文件路径。
- 终端意味着可以操作运行 DSH 的机器，因此只应向你信任的用户和网络开放 DSH Web。

## 已知限制

- 已打开标签和未保存草稿只存在于当前页面，刷新后会丢失。
- 文件编辑器只读取文本；图片以预览渲染，其他二进制文件只显示二进制变更提示，不渲染内容。
- 关闭标签、刷新页面、连接断开、切换工作区或停止插件都会结束终端进程；终端的可用性与并发数遵循宿主自身的终端配置。
- DSH 目前没有公开的对话栏位置 API，因此插件通过官方 AppFrame 的稳定标记调整列顺序。未来 AppFrame 重构后可能需要同步更新插件。
- 结构化查看器对超大 CSV/JSON 设有大小、节点和深度上限以保证流畅；超出上限的内容会以源码或截断形式展示，而非完整渲染。
- 在 Windows 桌面版中，收起后的侧栏宽度为零，DSH 会隐藏侧栏的浏览区和底栏；此时模式切换与中栏开关不可用，重新展开侧栏即可恢复。macOS、浏览器和 Linux 下收起侧栏仍保留图标栏，两个控件都可继续使用。
- 窗口非常窄时，AppFrame 官方让步规则会暂时关闭中栏，宽度恢复后再自动打开。

## 开发

需要 Node.js 24 或更高版本，以及兼容的 DSH 开发工作区。

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run test:bundle
```

`npm run typecheck` 除了插件源码，还检查模拟 DSH 快照的测试桩（`workspace-binding`、`workbench-sidebar`、`workbench-editor`）：宿主类型变更会直接让构建失败，而不是静默关掉这些检查。部分其余测试文件暂未做类型检查。

修改 `src` 后必须执行 `npm run build` 重建 `lib/client.js`，DSH 客户端加载的是构建产物而非源码，之后才会生效。
