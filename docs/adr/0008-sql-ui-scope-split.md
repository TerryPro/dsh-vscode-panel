# SQL 界面职责划分：连接面在中栏，结构面在侧栏，状态条只报别人没说的事

需求：`.sqlnb` 笔记的工具条与左栏 SQL 面板各画了一套连接控件（数据库下拉、档别下拉、重新扫描、连接/断开、连接状态读数），两处功能重复，读者不知道哪套是正牌；工具条本身也被这一整块挤得放不下。

决定：**连接归中栏笔记工具条，结构归左栏面板，状态条只报其它界面当时没说的那部分**。三条各自的职责：

- **中栏 `.sqlnb` 工具条**：单元格动作（保存、增格、运行、清空、取消）+ 连接的全部（选库、选档、重扫工作区、连接、断开、状态读数、连接被拒的原因，以及内存库与 WAL 伴生文件这两条关于当前连接的常驻说明）。控件集合没有改变，只是接过了原本在侧栏的那些说明。
- **左栏 SQL 面板**：只有结构。连上的那个库的表/视图/列、展开列、双击插入 `SELECT *`、表行右键菜单，以及面板头部唯一的一枚「刷新结构」。
- **编辑器状态条**：源码视图下报完整读数；单元格视图下让位，只报工具条说不出来的事（库文件已不可访问、需要重连）。

理由分两层。控件的重复不是视觉问题而是**规则要写两遍**：内存库没有档别、连接后不许换库换档、扫描有上限要明说——每条都得在两个组件里各实现一次，任何一次遗漏都是一个界面遵守另一界面不遵守。职责不清则来自这套重复本身：两个长得一模一样的数据库下拉并列时，读者无法判断点哪个作数。

判断"哪一处该留下"用的是本仓已经写下的一条判据（提交 `ca2296c`）：**提示留在离它解释的东西近的那一处，远的那份是噪音**。按这条，库文件列表搬到工具条后，关于列表的说明（扫描截断、内存库、WAL 伴生文件）跟着搬过去；而解释"为什么这棵树是空的"那句话留在面板，因为它解释的是面板自己的空。

## Considered Options

- **面板为唯一连接面，工具条只留一枚状态胶囊**：表单（字段标签、内存库无档别、WAL 说明、断开前会丢中间成果的警告）本来就属于一个控制台，塞进工具条只剩两个裸下拉。被否：连接是这份笔记的属性，写它的地方应该在看着它写的地方；而且笔记工具条在侧栏收起时是唯一还在场的界面。
- **两处都留，抽成一个共享控件组件**：只消除样式与行为漂移，不消除"哪套作数"。被否：共用状态源已经保证两处不会互相矛盾（面板读的就是笔记那份 per-tab runtime），重复的代价从来不是矛盾，是每条新规则要写两遍。
- **工具条的连接区收成胶囊 + 弹层**：一次解决"太挤"。被否（本轮）：它会动到连接语义，而连接语义的改动应当单独评审；工具条的控件集合保持不变，本轮只搬职责。

## Consequences

- **本决定反转工单 [#16](https://github.com/TerryPro/dsh-vscode-panel/issues/16) 的票面**（"侧栏放连接选择器 + schema 树"）。票已关闭，正文不改写，由新工单与本篇互指。此前没有任何 ADR 决定过面板与工具条的界面归属——ADR 0002/0007 决定的「连接归笔记」说的是连接的生命周期归谁，不是控件放哪。
- **`SqlPanel.tsx` 原先那句自陈作废**：「面板上每个按钮都是笔记界面也提供的，所以两边不可能对连接各说各话」。现在的保证方式是不再有两套按钮。
- **`connectionReadout` 只剩两处消费方**（工具条与状态条），而且这两处按视图互补、不再同屏重复。`sql-connection-readout.ts` 那段"三处必须一致"的理由随之失效。
- **面板不再扫描工作区**：那次遍历只为填库下拉，下拉走后面板没有东西可喂。库文件列表因此只剩工具条一处——侧栏收起时看不到，这是接受的结果，因为连接本来就该在笔记里做。
- **未连接的侧栏是一句死路的说法**：面板没有连接控件后，"未连接"必须同时指出入口搬去了哪，否则读者在一栏里看到一个事实却没有下一步。
- **状态条的读数与工具条互补，照的是 `NotebookKernelStatus` 已有的 `hideChip` 规则**（状态条只说别的界面没说的事），不是新发明的口径。
- 面板写回笔记的手势（双击插查询、右键菜单四项）留在面板，因为它读的是结构、写的是一份新格；这个方向（侧栏写进笔记）不变。
- 一条既有缺陷**不在本轮修**：工具条的库下拉在连接后仍可改，而那个位置此刻是「断开」，于是下拉可以显示一个并未连上的库，同时读数显示实际连上的那个。修它要在行为上动工具条，与本轮"只搬职责、不动工具条行为"的边界冲突，另开票。
