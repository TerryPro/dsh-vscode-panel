# SQL 笔记：结果集的行以数组返回，而不是以对象返回

需求：查询结果要渲染成表格、要能导出。看起来无关紧要的选择是宿主内部怎么表示一行。

决定一律用 `statement.setReturnArrays(true)`，行是值数组，列名与列序取自 `statement.columns()`，两者按下标 1:1 对齐。理由：`DatabaseSync` 默认的对象行以列名为键，而 SQLite 允许同名列——实测 `SELECT 1 AS x, 2 AS x` 返回的是 `{"x":2}`，第一列的值**永久丢失**且无从还原；`SELECT * FROM 表A, 表B` 会把两张表同名的列吃掉一个（实测 5 个真列只剩 4 个键）。丢掉之后不能补救：`columns()` 虽然完整保留每个同名项，但拿它去给对象行补名只会把同一个值复制三遍。

## Consequences

- 面向用户显示的是**列标签**（同名列加以区分），真列名与声明类型随元数据保留；两者是两件事，见 GLOSSARY.md。
- 归一化必须逐值判类型：`readBigInts` 不开时任何超出安全整数范围的值都**直接抛错**（用户一句普通 SELECT 就会整条查询失败），所以必须开；开了之后所有整数都变成 BigInt（`42` → `42n`），而 BigInt 进 `JSON.stringify` 会抛。
- 不采用 SQL 层加唯一别名的替代方案：那等于改写用户写的语句，与"不改写用户 SQL"的既有决定相冲。
