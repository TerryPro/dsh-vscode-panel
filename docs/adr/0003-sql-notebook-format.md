# SQL 笔记用新的工作区文件格式 .sqlnb

需求：SQL 笔记要落成工作区里的文件（只存源文本，不存结果）。备选是复用 `.ipynb` 并把 SQL 写进 code 格，以及用普通 `.sql` 加 `-- %%` 分隔注释。

决定用自定义 JSON 格式 `.sqlnb`，字段只有版号、格序、格类型与源文本。理由：`.ipynb` 会把 `execution_count`、`outputs` 这些 Jupyter 专有字段写进用户的仓库，而那种文件跑不了真内核，格式在撒谎；`.sql` + 注释分隔虽然 diff 最干净，但表达不了格类型（本模块要支持 markdown 说明格）与版号，且每个读它的工具都得先认这套注释约定。代价是要新写一份解析与写回，并给扩展名接入文件树、打开链路与视图分派。

## Consequences

- 解析必须永不抛：文件被手改坏、版号不认识、字段缺失时降级为只读错误态并指出哪一格有问题，绝不自动重写文件（与笔记本 `parseNotebook` 的先例一致）。
- 结果不进文件，所以执行、清空输出都不标脏；这与笔记本"cell_completed 时把输出写回 draft"的行为相反，改共用单元格视图时不要顺手抄过来。
