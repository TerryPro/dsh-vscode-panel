# `.sqlnb` 记下连接配置与查询结果（部分推翻 ADR 0003）

需求：SQL 笔记要把数据库配置与查询结果都存进 `.sqlnb`，重开笔记时按记录自动连上并直接看到上次的结果。

ADR 0003 定的是"只存源文本，不存结果，也不存连接引用"，并给出了两条理由：结果不进文件才能让"执行不标脏"成立；连接是会话态，把路径写进文件会让文件指向一个可能已经搬走的库。这两条理由都还成立，只是**权衡的结论变了**：一份重开就空白的笔记，读者每次都要重连、重跑，而这正是"笔记"这个词承诺要省掉的事。ADR 0003 的取舍在"文件干净"与"打开即可用"之间选了前者，这次选后者。

决定的形状，逐条对应 ADR 0003 里被推翻的部分：

- **文件记连接配置**，字段是库路径与档别（`connection: { path, access }`）。它是一个*记录*而不是活连接：打开笔记时拿它去连，连不上就照常报错并让读者从选择器里改，绝不自作主张回退到 `:memory:`——那会让第一格查询对着一个空库跑，"no such table"看起来像读者的错。
- **文件记每格结果**，与提示符序号、耗时一起（`results` / `execution_count` / `elapsed_ms`）。运行结束后由运行时折回 draft，并立刻走保存链路落盘。序号与结果**成对**写入或删除：只有结果没有 `[n]` 的文件在说一份来路不明的行。
- **写入时机是运行结束**。这是"打开就能看到上次结果"的必要条件；代价是文件会随每次执行变动，git diff 因此变大——这是明确接受的代价，选它的人要的是结果留得住。

## Consequences

- **"执行不标脏"这条不变式没有了。** 运行现在会改文件、标脏、并触发保存。ADR 0003 那句"改共用单元格视图时不要顺手抄过来"随之失效：现在两边都是运行完把结果折回 draft，与笔记本 `cell_completed` 的做法一致。翻这条旧结论时，改的是 ADR 0003 的这个 Consequences 条目，不是它的格式选择。
- **版本号升到 2，且 v1 保持可读可写。** v1 文件在首次需要 v2 字段的写入时升到 v2；普通编辑也会升版（写入路径统一抬版），因为一次写入不可能只改一半。版号不认识的文件仍然只读且绝不重写（ADR 0003 的这条完全保留）。
- **结果是持久数据，不再是可丢弃的视图状态。** 由此带出四条必须一起成立的行为，缺一条就会展示一个读者无法察觉的错误答案：
  - **连接动作不碰结果。** 打开笔记时先按文件恢复结果、再自动重连；重连**不重置**屏幕上已有的结果。首版把"连接目标变了"写成 `before === null || …`，于是首次连接恒等于"变了"，读者打开一份有结果的笔记会看着它连上、然后所有表消失。
  - 请求层失败（连接断了、库文件被删）时，该格记录的旧结果必须清掉，否则重开笔记会把上一次的表当作这次失败的答案显示出来；
  - 取消时同理：屏幕显示"已取消"，文件里不能还留着一张表；
  - 清空输出要连文件一起清，否则下次打开全部复活，与这个按钮的意思相反。
- **一条总不变式：屏幕上显示的就是文件里记的。** `hydrate`（按文件恢复）在 tab 绑定与连接关闭时各跑一次，中间任何连接、切换、断开都不许改动结果；结果是运行结束、运行失败、取消、或读者主动清空时才变的。断开连接尤其不能清屏——结果在文件里，清屏是在说"结果丢了"，而字节根本没被碰过。
- **无法改写的文件如实说明。** 版号不认识时结果记不进文件，界面在运行前就说清"结果只留在屏幕上"。不说的话，读者是在丢失工作之后才知道的。
- **自动重连不写回文件。** 打开时是按文件已有记录连的，再写一次会无端把每份重开的笔记标脏。连接记录只在读者主动连接时更新，且记的是宿主**实际授予**的档别，不是请求的档别——可写请求被占用挡回只读时，记成可写会让下次打开去要一个从未拿到过的档位。
- 与 ADR 0002 的边界不变：结果折回 draft 这件事两边做法相同了，但传输与会话仍完全分开，SQL 笔记依旧不进内核 registry、不进内核面板。
