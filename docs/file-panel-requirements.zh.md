# 文件管理面板需求分析

范围：侧栏「文件目录」模式，即 `src/client/files/**` 与宿主 `src/host/workspace-backend.ts` 的 `/tree`、`/entry/*`、`/path/*` 这条链路。编辑器、Git、终端的缺口不在本文内。

现状基线：懒加载单层目录、行内新建、同目录重命名、带风险确认的递归删除、复制相对/绝对路径、展开/折叠全部、Git 状态着色、手动 reveal、3 秒轮询刷新、按工作区记住展开集合。批量操作、拖拽、搜索、键盘导航这四块目前是空的。

---

## P0 · 先修的 bug

- **P0-1** 某个目录内容太多被截断时，也要像根目录那样提示「只显示了前面一部分」。
- **P0-2** 符号链接要在树里标出来，别等用户点开才报「不支持」。
- **P0-3** 文件被别的程序改了但大小没变时，树也要能发现；行上要能看到大小和修改时间。
- **P0-4** 文件名里的数字按大小排，`item2` 排在 `item10` 前面。
- **P0-5** 删除有未提交 Git 改动的文件时，要提醒这些内容删了就找不回来。
- **P0-6** 成功和报错的提示条几秒后自动消失，不要一直占着面板顶部。

## P1 · 只改客户端就能做完

- **P1-1** 键盘能操作整棵树：↑↓ 移动、←→ 折叠展开、Enter 打开、F2 重命名、Delete 删除。
- **P1-2** 树顶部加一个过滤输入框，边打字边筛掉不匹配的条目。
- **P1-3** 支持 Ctrl/Shift 多选，选中多个后可以一次删除。
- **P1-4** 单击文件先开成预览标签（会被下一次单击替换），双击才固定下来。
- **P1-5** 切换编辑器标签时，文件树自动展开并选中当前文件，这个行为可以关掉。
- **P1-6** 展开状态、选中项和滚动位置在页面刷新后还在。

## P2 · 需要宿主加接口

- **P2-1** 文件可以复制、粘贴、复制一份，也可以移动到别的目录（现在只能在同一个目录里改名）。
- **P2-2** 可以把本地文件拖进文件树，写进工作区。
- **P2-3** 可以右键把工作区文件下载到本地。
- **P2-4** 可以右键在系统文件管理器里打开所在位置。
- **P2-5** 可以右键在某个目录里新建终端（现在终端只能开在工作区根目录）。
- **P2-6** 可以右键把文件作为引用插入对话输入框。
- **P2-7** 提供 `files.exclude` 设置，`node_modules`、`dist`、`.venv` 这类目录默认不进树。
- **P2-8** 加跨文件搜索（Ctrl+Shift+F）和按文件名快速打开（Ctrl+P）。

## P3 · 仓库变大之后的性能账

- **P3-1** 列目录不要一个条目查一次属性，一次把类型拿全。
- **P3-2** 树做虚拟滚动，展开全部目录之后行数再多也不卡。
- **P3-3** 用事件推送或长轮询获知文件变动，取代每 3 秒重列所有已展开目录。

---

## 结论与排期建议

P0 让用户不再以为面板坏了；P1 让文件树日常能用、能用键盘用；P2 打通文件的进出工作区和进对话；P3 是仓库变大之后要还的性能债。

建议 P0 和 P1 连着做完再发版；P2 里先做 **P2-6**（只有站在 DSH 里才做得出的能力）和 **P2-1**（最基本的文件操作现在还缺一半）。

做的时候守本仓既有约束：新文案要同时进 `src/client/core/locales.ts` 的中英两本字典；新增宿主路由只接受工作区 id 与工作区相对路径；不引入 `ws` / `node-pty` 之类的原生依赖；每条 P 项都要留下能在改坏时变红的测试，并把测试文件加进 `tsconfig.test.json` 的 `files` 白名单。
